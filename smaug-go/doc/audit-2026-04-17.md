# Post-Phase-5 Audit — 2026-04-17

Manager-coordinated audit following completion of Phase 5 Tier 5. Four independent adversary reviews ran in parallel: phase-completeness, Go idiom, security + usability, and a C-vs-Go capability comparison. Baseline: `go build ./...` clean, `go vet ./...` clean, `go test -count=1 ./...` all 15 packages pass, 1,962 test functions, ~72k Go LOC vs ~190k C LOC.

**Overall verdict:** **CONCERNS.** No critical regressions. Port is architecturally sound and measurably better than the C original on safety, testability, and build determinism. Material gaps in combat depth, player-config commands, and documentation accuracy.

## Consolidated findings

### Critical / High severity

#### C1. PC multi-attack skills are not applied in combat
**Files:** `internal/combat/combat.go` (grep confirms no reference to `second_attack`/…/`seventh_attack` or `SecondAttack`), vs C `src/fight.c:1058–1132`.
**Behavior:** A level 30 warrior gets one attack per round in Go where C would give 3–5 (second/third/… attack skills). This is the primary martial progression mechanic in C SMAUG.
**Recommendation:** Port the multi-attack loop from `src/fight.c:1058–1132`. Needs `util.NumberPercent` vs `Learned[gsn_second_attack]` gating each extra `OneHit`.

#### C2. Weapon proficiency bonus absent
**Files:** `internal/combat/combat.go:OneHit` (no call to any proficiency helper), vs C `src/fight.c:1385–1566`.
**Behavior:** Wielding your class's proficient weapon does nothing in Go. C modifies hit chance and learn-from-success chance.
**Recommendation:** Port `weapon_prof_bonus_check` into `combat/`, call from `OneHit`.

#### C3. Stances stored but never applied
**Files:** `internal/act/skills4.go:183` (`DoStance` sets `ch.Stance`), `internal/combat/combat.go` (grep confirms zero references to `Stance`), vs C `src/fight.c:1058–1070`.
**Behavior:** The field round-trips through save/load correctly, but has no gameplay effect.
**Recommendation:** Either implement the GM-stance attack bonus per C, or explicitly document the field as cosmetic-for-now.

#### C4. `TestSpellFarsight_Success` is 5% flaky
**File:** `internal/magic/spell_group_a_test.go:64–79`.
**Cause:** `SpellFarsight` calls `SavesSpellStaff(30, victim={Level:10})` → save chance floors at 5%. The test has no RNG seeding and no determinism hook.
**Doc claim:** `phase5-tier5-testclient.md:27` says "observed stable under `-count=3`" — that is documentation of a known flake, not a fix.
**Recommendation:** Either set `victim.SavingSpellStaff` very negative to force the 95% fail floor, or add a `rollSaveFunc` injection point mirroring `spell_smaug.go:409`.

#### C5. `phases.md` Phase 3 deliverables overstate what shipped
**File:** `doc/phases.md:152–168`.
**Claims not delivered:** "all spell functions from magic.c" (delivered in phases 4/5), "councils: similar to clans" (no council commands exist), "deities: prayer, favor tracking, deity-specific effects" (no `DoPray`), "rfind" (absent), "clans: promote/demote" (absent).
**Recommendation:** Rewrite the Phase 3 section to match `phase3-completed.md`, or add a note that the plan section is aspirational and the completion doc is authoritative.

### Medium severity

#### M1. `mpForce` partially re-opens the S3 trust-cap fix
**File:** `internal/mudprog/commands.go:117` — `CmdRegistry.Interpret(victim, cmd)` instead of `InterpretWithTrustCap`.
**Scenario:** Crafted area with `mpat <room> mpforce <imm> <command>` runs the command at the immortal's full trust. Gated by registry-level checks but bypasses the extra cap.
**Recommendation:** Call `InterpretWithTrustCap(victim, cmd, mob.GetTrust())`.

#### M2. `DoSaveArea` is non-atomic
**File:** `internal/act/olc.go:747` — `os.Create(path)` truncates live `.are` file before write.
**Scenario:** Crash or disk-full mid-save leaves the area corrupted. S10 fixed this for player files but `savearea` was missed.
**Recommendation:** Write to `path + ".tmp"` then `os.Rename`.

#### M3. Missing communication channels
**Files:** not registered in `internal/boot/boot.go`.
**Missing:** `channels`, `immtalk`, `auction`, `gtell`, `music`, `newbiechat`, `racetalk`, `wartalk`, `ordertalk`, `counciltalk`, `guildtalk`.
**Recommendation:** Inventory and prioritize. `immtalk`/`gtell`/`auction` are most player-visible.

#### M4. Missing player-config commands
**Files:** not registered in `internal/boot/boot.go`.
**Missing:** `config`, `afk`, `bio`, `title`, `password`, `ignore`, `dnd`, `description`, `pagelen`, `ansi` (some of these may have partial impls — verify before porting).
**Note:** `alias` IS registered (`boot.go:567`). The C→Go audit was slightly off on that one.
**Recommendation:** At minimum `password`, `title`, `afk` — expected by any MUD player.

#### M5. `do_save` player command not registered
**File:** `internal/boot/boot.go` — only `savearea` (immortal) is registered.
**Behavior:** Players cannot manually type `save`; autosave covers the normal case (timer + on-quit).
**Recommendation:** Register `DoSave` (may need to create it) that calls the existing save path.

#### M6. Test-count numbers in Tier docs are not reconcilable
**Files:** `phase5-tier3-completed.md:3` ("2,205 top-level test cases") vs `phase5-tier4-content.md:5` ("~1,914 top-level tests") vs actual `func Test*` count of 1,962.
**Cause:** Inconsistent counting methodology (top-level vs sub-tests) between tier docs.
**Recommendation:** Pick one methodology, note it at the top of the docs.

#### M7. `OprogCommandTrigger` is a wired-but-dead hook
**File:** `internal/mudprog/oprog.go:216–220` — unconditionally returns false.
**Behavior:** CMD obj-progs never fire. The hook is wired in `boot.Boot`, so any area relying on CMD obj-progs is silently broken.
**Doc status:** Correction — this IS documented in `phase5-tier3-completed.md:85` under "Known deferrals (not load-bearing)". The audit finding was a false positive on the doc-status check. The stub itself remains; port is still a Phase 6 candidate.
**Recommendation:** Port the wordlist-match logic from C `rprog_wordlist_check` when Phase 6 work touches the mudprog driver.

#### M8. No clan/deity write path in `persist/`
**Files:** `persist/subsystems.go` has `LoadClansFromDir` / `loadDeity` but no corresponding save functions.
**Behavior:** Runtime changes to clan/deity state (via hypothetical future imm commands) don't persist across reboots.
**Recommendation:** Add `SaveClan`/`SaveDeity` when the first set/mutation command lands — track as prerequisite.

#### M9. Boot-time subsystem failures downgrade to warnings
**File:** `internal/boot/boot.go:199, 212, 225` — classes, races, skills all log `WARNING` then continue.
**Scenario:** Misconfigured `-data` path produces a server that boots and accepts connections but has no classes/races/skills. Players hit immediate character-creation failures.
**Recommendation:** Return error from `bootDB` when classes, races, or skills fail to load. Fail fast, fail loud.

### Low severity

#### L1. Alias count unbounded
**File:** `internal/act/cmds2.go:299` — no cap on `len(ch.PCData.Aliases)`.
**Scenario:** Script-driven alias-creation loop exhausts memory; alias expansion is O(n) per command.
**Recommendation:** Cap at 50 aliases.

#### L2. `math/rand` used alongside `math/rand/v2`
**Files:** `internal/act/quest.go:4,67,188`; `internal/act/cmds2.go:5,231`. `internal/util/dice.go` uses `math/rand/v2`.
**Recommendation:** Route through `util.NumberRange`.

#### L3. `interface{}` instead of `any` in new code
**File:** `internal/testclient/client.go:265` (`func (c *Client) fatalf(format string, args ...interface{})`).
**Recommendation:** Change to `...any` for consistency.

#### L4. `testclient.readUntilErr` per-iteration `string()` + `ToLower` allocations
**File:** `internal/testclient/client.go:71,84`.
**Recommendation:** Use `bytes.ToLower` + `bytes.Index` on the `[]byte` buffer.

#### L5. `fillOnce` allocates 4KB scratch per call
**File:** `internal/testclient/client.go:222`.
**Recommendation:** Promote `tmp` to a `Client` field.

#### L6. Brute-force lockout closes connection without explanation
**File:** `internal/game/loop.go:387–390`.
**Recommendation:** Send "Too many password failures — disconnecting." before closing.

#### L7. MXP protocol support absent
**Files:** C `src/protocol.c` has MXP tag parsing; Go has no equivalent.
**Recommendation:** Defer to Phase 6 — out of scope for current phases.

## Positives (genuinely well-done)

1. **All prior S1–S16 security fixes held.** bcrypt, connection limit, trust cap, brute-force lockout, atomic player save, IAC bounds, scanner limits, path traversal defenses all survived Phase 5 Tier 1–5 additions.
2. **`internal/boot` + `internal/testclient` isolation is well-engineered.** Package-level mutex serializes Harness instances to protect package-global hook vars from `t.Parallel()`; per-test `TempDir()` copy of fixture data prevents concurrent-cleanup races. Comments explain *why* the isolation is needed.
3. **`combat/dammessage.go` uses `[18]*[24]string` tables** — pointer-to-array sharing across blade/blunt/generic message slices, zero duplication, no alloc at call time.
4. **`mudprog/sleep.go` re-entrancy handling** — snapshot-and-replace pattern with `kept := snapshot[:0]` avoids aliasing without locking, documented inline.
5. **Data-file compatibility is solid.** `.are` round-trips read→parse→write; player save files format-match the C keyword-value layout; `skills.dat`, `.class`, `.race` load cleanly from the shipped `db/`.
6. **Test infrastructure is the single largest improvement over C.** 1,962 top-level test functions across 15 packages, including a full in-process integration harness that drives real telnet sessions. C has zero automated tests.
7. **Pure Go, no Cgo, single static binary** — zero external runtime dependencies. Build determinism is perfect.

## Meta-finding: the port is ~34% of the C command surface

C `tables.c` declares ~599 `do_*` entries; Go registers 205 in `internal/boot/boot.go`. Most of the missing 394 are one of:

- Internal `do_mp*` mudprog commands — correctly absent as player-facing commands (they're Go functions called directly by the driver).
- Vestigial 1998-era features: ICQ, homepage, email, HTTP/DNS embedded servers, casino gambling, rolldice.
- Phase 5 optional candidates: overland, housing, polymorph, archery, stances (stored but unapplied), dragon flight, arena, planes, holidays, star maps, hotboot, marriage. These are all documented as out-of-scope.
- Player-visible config/channels (see M3, M4) — should be prioritized.
- Administrative immortal utilities (`pset`, `pstat`, `sset`, `stset`, `vstat`, `memory`, `wizlist`, `zones`, `vnums`) — lower priority.

The port is a playable MUD today. It is not a drop-in for a production C SMAUG server.

5. **Communication channels (M3):** `immtalk`, `gtell`, `auction` — these keep the social fabric of the MUD working.
6. **`phases.md` cleanup (C5):** the authoritative summary doc should not mislead future readers.
